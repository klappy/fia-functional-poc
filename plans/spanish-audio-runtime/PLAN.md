## Build contract and exact ownership

Produce public Spanish audio manifest only from accepted D request/owner/source bindings plus independently accepted synthesized outputs. For each unique request require processedText+SHA, provider-output SHA/bytes/MIME/path and decode/duration evidence; no private voice IDs/route/account fields. Every owner maps to a request, retains source-input SHA, source identity, classification, notice IDs and playbackGroupId. Manifest sourceSha256 for AudioController equals processedTextSHA and queue item.text is that exact processed text; original source SHA remains separate and verified by the build. Do not hash raw HTML against processed speech accidentally.

Build an explicit owner lookup from ledger objects, not title matching: original guide owner IDs map through source.packPointer/block identity; original editions map through repository/verseId; derived edition owners through editionID+verse; original term/media/supplement owners map through source IDs/pointers; A-derived IDs remain namespaced. Shared dedup request ID identifies bytes, while logical sourceOwnerId/domain/parent anchor remains separate. Assert every playable source has a mapping and every mapping targets an existing accepted source. Missing recordings make that item unavailable; do not silently queue another item's file.

A pure Spanish queue resolver returns ordered content and notice items plus original logical owner, playback group, guide anchor and terminal content identity. Notice requests precede the first content in an actual group; deduplicate ordered notice IDs within that group. Original and derived Scripture group by edition, not verse. Resuming or restoring mid-group resumes exact clip/gap without replaying notices; a new deliberate playback of a group includes its notices. Restart semantics: restart current content recording using existing control; explicit replay of whole group starts group notices. Notice completion never counts as content completion or promotes Next. Keep notice/title/source attribution distinguishable; metadata-only English legal strings are never automatically narrated.

Guide playback queues the selected semantic group's ordinary blocks only and stops at its actual discussion boundary. No auto-advance to the next guide group and no discussion completion inference. Optional guide example group and repentance enactment require explicit opt-in; closing optional modal restores core position and does not autoplay. Guide terminal content completion may expose same-group Scripture/resource ready action using existing nested-ready precedence: selected edition/explicit valid resource, otherwise stable source order. Guide Next remains guide adjacency even when nested Scripture/resource owns playback. Paused owner wins; stale ended events, restored offsets or elapsed heuristics cannot create completion. Preserve the accepted primary priority: center primary when ready; eligible Next primary only on live current content completion; then center Replay secondary. Notice-only ended is excluded.

Resource card/detail play queues its body/title and accepted required supplemental repairs in explicit source order; optional enactment remains separately selectable. Filtered resources determine Prev/Next adjacency; changing selection cancels/replaces old playback with generation fencing. Persist a validated Spanish audio checkpoint separately from text position (request/source/output hashes, logical owner/group/anchor, offset and phase); restore paused only.
